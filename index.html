核心邏輯

純多方策略。收盤價連續 2 根站上 1280 根K棒 High 均線、且均線本身連續 2 根上揚才進場；出場完全不主動停損停利，只靠每月第三個週三結算日強制平倉。近似「趨勢一旦確立就抱到底」的買進持有邏輯。

主要優勢

風險與適用情境

最大策略虧損擴大到 -140.0%（原零成本版為 -113.2%），因為完全沒有主動風控，遇到單次大幅拉回會直接承受。適合能接受較大帳面波動、以長期總報酬效率為優先的使用者。

核心邏輯

在 v1 的 1280 HighMA 趨勢濾網上，疊加 MACD 柱狀圖 > 0（動能確認）與 RSI > 50（多方力道確認）雙重過濾；出場改用 BB(20,2) 中軌動態跌破（僅獲利時觸發）＋結算日強制出場。相較 v4/v5 用 BB 下軌，v3 用中軌出場明顯更敏感、更早停利了結。

主要優勢

計入單邊2,000點成本後，勝率從零成本版的 90.35% 掉到 69.83%，帳戶所需金額也從六版最低升到 848,600 元——v3 在六款核心策略裡已不再持有任何一項最優或次優指標，是本次改用真實成本後跌幅最明顯的版本。

風險與適用情境

交易總次數 759 筆是六版中第二高，對交易成本高度敏感；曾以 v3.1 加入 10 根K棒冷卻期測試，交易次數幾乎沒變，證實瓶頸不是缺乏冷卻期，而是 BB 中軌出場本身過於敏感、獲利常常提早了結，導致單筆平均獲利被壓得很薄、扛不住每筆 2,000 點的來回成本。這款是本頁最直接示範「零成本回測會嚴重高估高頻策略」的案例。

// ======================================================
// 1. Core trend and multi-dimensional technical indicator calculation
// ======================================================
HighMA = Average(High, TrendLen);

// Calculate MACD (assess breakout momentum)
MacdValue = MACD(Close, MacdFastLen, MacdSlowLen);
MacdAvg = XAverage(MacdValue, MacdMacdLen);
MacdDiff = MacdValue - MacdAvg; // MACD Histogram

// Calculate RSI (assess bullish strength)
RsiValue = RSI(Close, RsiLen);

// Calculate Bollinger Bands midline (dynamic trailing stop)
BBMid = Average(Close, BBLength);


// ======================================================
// 2. Settlement day condition check
// ======================================================
IsSettlementDay =
    DayOfWeek(Date) = ExitDay
    and DayOfMonth(Date) >= MinDay
    and DayOfMonth(Date) <= MaxDay;


// ======================================================
// 3. Entry logic (Trend + Momentum + Strength confirmation)
// ======================================================
Condition1 =
    // Original logic: Price above 1280 HighMA and MA rising for 2 consecutive bars
    Close > HighMA
    and Close[1] > HighMA[1]
    and HighMA > HighMA[1]
    and HighMA[1] > HighMA[2]
    // New filter: MACD histogram > 0, ensuring upward momentum
    and MacdDiff > 0
    // New filter: RSI > 50, ensuring bullish control zone
    and RsiValue > 50;

// Execute long entry
If MarketPosition <> 1 and Condition1 then
    Buy ("LongEntry_Opt") Next Bar at Market;


// ======================================================
// 4. Exit logic (Dynamic trailing stop + Mandatory settlement exit)
// ======================================================
If MarketPosition = 1 then 
begin
    // Dynamic stop: Exit if close falls below 20-bar BB midline and position is profitable
    If Close < BBMid and OpenPositionProfit > 0 then
        Sell ("BB_TrailExit") Next Bar at Market;

    // Settlement day final defense: Hold until the close of the 3rd Wednesday
    If IsSettlementDay then
        SetExitOnClose;
end;

// Strategy Name: TXF_15M_VolKD_CoolDown_Settlement_v4

Inputs:
    TrendLen(1280),
    ExitDay(3),
    MinDay(15),
    MaxDay(21),
    // Live Volume filter parameters
    VolLen(20),
    VolMult(1.5),
    // KD Oscillator parameters
    KLen(9),
    DLen(3),
    // Bollinger Bands exit parameters
    BBLength(20),
    BBDev(2),
    // Cooldown parameter to prevent over-trading
    CooldownBars(10);

Variables:
    HighMA(0),
    AvgVol(0),
    LowestLow(0),
    HighestHigh(0),
    KValue(0),
    DValue(0),
    BBLower(0),
    ExitBar(-999),
    CanEnter(true),
    IsSettlementDay(false),
    Condition_Trend(false),
    Condition_Vol(false),
    Condition_KD(false);

// ======================================================
// 1. Core trend, live volume, and KD calculations
// ======================================================
HighMA = Average(High, TrendLen);
AvgVol = Average(Volume, VolLen); 

// Calculate KD (Stochastic Oscillator)
LowestLow = Lowest(Low, KLen);
HighestHigh = Highest(High, KLen);

If HighestHigh <> LowestLow Then
    KValue = (Close - LowestLow) / (HighestHigh - LowestLow) * 100
Else
    KValue = 0;

DValue = Average(KValue, DLen);

// Calculate Bollinger Bands Lower Band (Relaxed dynamic stop)
BBLower = Average(Close, BBLength) - BBDev * StandardDev(Close, BBLength, 1);


// ======================================================
// 2. Cooldown period logic (Prevent consecutive whipsaws)
// ======================================================
// Record the bar number when a long position is closed
If MarketPosition = 0 and MarketPosition[1] = 1 Then
    ExitBar = CurrentBar;

// Check if enough bars have passed since the last exit
CanEnter = (CurrentBar - ExitBar) > CooldownBars;


// ======================================================
// 3. Settlement day condition check
// ======================================================
IsSettlementDay =
    DayOfWeek(Date) = ExitDay
    and DayOfMonth(Date) >= MinDay
    and DayOfMonth(Date) <= MaxDay;


// ======================================================
// 4. Entry logic (Trend + Volume Burst + KD Confirmation)
// ======================================================
Condition_Trend =
    Close > HighMA
    and Close[1] > HighMA[1]
    and HighMA > HighMA[1]
    and HighMA[1] > HighMA[2];

// Volume burst requirement
Condition_Vol = Volume > (AvgVol * VolMult);

// KD golden cross and not in overbought territory
Condition_KD = KValue crosses over DValue and KValue < 80;

// Execute long entry if all dimensions align and cooldown is cleared
If MarketPosition = 0 and CanEnter and Condition_Trend and Condition_Vol and Condition_KD then
    Buy ("Long_v4") Next Bar at Market;


// ======================================================
// 5. Exit logic (Relaxed Trailing Stop + Settlement)
// ======================================================
If MarketPosition = 1 then
begin
    // Relaxed dynamic stop: Exit if close falls below the BB lower band
    If Close < BBLower and OpenPositionProfit > 0 then
        Sell ("BB_TrailExit") Next Bar at Market;

    // Settlement day final defense
    If IsSettlementDay then
        SetExitOnClose;
end;

// Tab Name: 15M_MacdRsiBB_BH_v1_1

// v1.1 design note:
// v1 is the highest net-profit / profit-factor version in the whole v1~v11
// series, built on a pure "buy and hold to settlement" idea: enter once
// price is above a rising 1280-bar High MA for 2 consecutive bars, then do
// nothing active until the settlement exit. Its only clearly weak year in
// the annual breakdown is 2022 (net -800, only 8 trades, 25% win rate) --
// a choppy year where the trend filter alone was not enough to keep the
// entries clean.
//
// v1.1 keeps v1's core idea and its exit side completely untouched (still
// no active stop, still settlement-exit only) -- only the ENTRY filter is
// tightened, by requiring three more conditions to all agree, each of them
// also confirmed for 2 consecutive bars (not just the current bar), on top
// of the original trend filter:
//   - MACD histogram > 0 for 2 bars (borrowed from v3's momentum filter,
//     but v3 only checks the current bar; here it must hold twice in a row)
//   - RSI > 50 for 2 bars (borrowed from v3's strength filter, same 2-bar
//     upgrade)
//   - Close > 20-bar BB midline for 2 bars (new filter: price must be on
//     the strong side of its own short-term mean, not just above the very
//     long-term trend line)
//
// Rationale: a choppy year like 2022 tends to lose money through a small
// number of marginal entries that only just barely satisfy a single-bar
// filter. Requiring five independent signals (trend direction, trend
// persistence, momentum, relative strength, and short-term price position)
// to ALL agree for two consecutive bars is meant to filter out exactly
// those marginal "just barely qualifies" entries, without adding any new
// exit-side risk control.
//
// IMPORTANT CAVEAT (read before backtesting): this design was reasoned
// about specifically to address v1's one weak year (2022) inside the
// existing ~9-year-4-month sample. That is a real overfitting risk -- a
// filter tuned to fix one historical year is not guaranteed to generalize
// out of sample. The real test is whether TOTAL net profit / profit
// factor / trade count across the FULL period improves versus v1, not
// just whether 2022 alone turns positive. Also note: stacking five
// independent 2-bar-confirmed conditions is a much stricter gate than
// v1's single 2-bar trend filter, so expect materially fewer trades than
// v1's 103 -- if too few trades survive, this version may also miss some
// of the large sustained trends that produced v1's biggest wins, since
// entries now confirm later in the move. And because the exit side is
// unchanged (no ISL, no BB trail), any entry that still slips through as
// a false signal still rides all the way to the next settlement day with
// zero active risk control, exactly as in v1.
